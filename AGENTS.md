# AGENTS.md — konwencje repo qa-tools

Ten plik jest ładowany automatycznie przez Vibe (instructions asset). Trzymaj się go przy każdej pracy w tym repo.

## Konwencje testów (projektowe)

- Testy w `tests/` (`e2e/`, `api/`); uruchamianie: `npx playwright test`.
- Selektory: `getByRole` / `getByLabel` / `getByText` / `getByTestId` — nigdy CSS/XPath.
- Asercje tylko przez `await expect(...)` — **zakaz `waitForTimeout`**.
- Każdy test niezależny; czyszczenie danych w `afterEach`.
- Nazwy testów: `should <rezultat> when <warunek>` (po angielsku).

## Struktura pluginu

- Plugin: `.vibe/plugins/qa-tools/` (manifest `plugin.json`, Agent Plugins 1.0).
- Skille: `skills/<name>/SKILL.md` — frontmatter `name`, `description` ("Load this skill when..."), `user-invocable: true`; jedna emotka na nagłówku `##` (konwencja w CONTRIBUTING.md).
- Agenci: `ai.mistral.vibe/agents/*.toml` — klucze snake_case, `schema_version = 1`, `agent_type = "subagent"`.
- Hooki: `ai.mistral.vibe/hooks.toml`; wiedza: `ai.mistral.vibe/knowledge/<name>/KNOWLEDGE.md`; MCP: `mcp.json` w root pluginu.
- Komendy projektowe: `.vibe/prompts/*.md` (przesłaniają globalne `~/.vibe/prompts/`).

## Zasady pracy

- Przed commitem: `python scripts/validate-plugin.py` (exit 0) i `python -m unittest discover -s tests` — oba zielone.
- Wersjonowanie: bump w `plugin.json` + wpis w `CHANGELOG.md` (`### 📦 Added` / `### 🐞 Fixed` / `### 🔄 Changed`); tag `vX.Y.Z` robi workflow `release.yml` automatycznie.
- Liczby w README (`**N subagents**`, `**N skills**`) muszą zgadzać się z faktyczną liczbą plików — walidator to sprawdza.
- Commity opisowe, po angielsku, z dopiskiem `Generated by Mistral Vibe.` + `Co-Authored-By: Mistral Vibe <vibe@mistral.ai>`.
- Żadnych sekretów w repo; dane testowe tylko fikcyjne.
