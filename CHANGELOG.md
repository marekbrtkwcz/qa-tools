Komunikat pokazuje bundla i numer linii; dopuszczalne oba typy cudzysłowu. Testy: podwójny i pojedynczy cudzysłów przechodzą, bare wersja → error z bundlem i linią, puste `version:` → error (też nie da się podbić).

Schemat pluginowego `mcp.json` dopuszcza `args` (zweryfikowane wobec `mcp.schema.json`), ale **nie** pól timeout i wersji — wersja wciąż żyje w globalnym installu (pływające `@latest` w README bez zmian), a `startup_timeout_sec`/`tool_timeout_sec` dalej tylko user-level; wpis user-level o tej samej krótkiej nazwie nadal shadowuje całą kopię pluginu. `GLOBAL_BINARY_SERVERS` (teraz eksportowana) to jedyne źródło mapowania nazwa→binarka+flagi: build emituje `args` z tej tabeli, testy porównują manifest z nią (single source of truth) i pilnują, by w `args` nigdy nie wkradła się przypięta wersja.
- **`qa-mcp`: ujednolicone nazewnictwo serwerów MCP — krótkie nazwy produktowe** — serwer Chrome DevTools MCP zmienia klucz `chrome-devtools-mcp` → **`chrome-devtools`**, więc oba serwery w bundlu (i wszędzie indziej) trzymają jedną konwencję: krótka nazwa „produktowa" (`playwright`, `chrome-devtools`), celowo **nie** nazwa binarki (`playwright-mcp`, `chrome-devtools-mcp` — te zostają w `command`). Shadowing działa po nazwie serwera bez zmian: user-level `[[mcp_servers]]` o tej samej krótkiej nazwie dalej zastępuje kopię pluginu zamiast spawnować drugą przeglądarkę. `bundles.yaml` (lista `mcp:` + komentarze), `GLOBAL_BINARY_SERVERS` w `build.js` (nazwa → binarka to teraz jedna tabela — specjalny branch dla `playwright` zlikwidowany), generator `mcp.json` dostał twardą bramkę: nieznana nazwa serwera to błąd builda i brak zapisu manifestu (zamiast cichego `command: server`), README (sekcje „MCP bez duplikatów" i „Nazwy serwerów ujednolicone"), testy: manifest z dwoma serwerami + nowy test na nieznany serwer.
- **`qa-mcp`: serwer Playwright MCP startuje z globalnego binarnego zamiast npx; instalacja pływająca `@latest`, piny wersji zlikwidowane** — `mcp.json` generuje teraz `command: "playwright-mcp"` (bare executable). Motywacja: Vibe daje MCP-om z pluginów twardy budżet 10 s na handshake `initialize`, a schemat pluginowego `mcp.json` (`extra="forbid"`) nie ma pola timeout; `npx` na Windows (shim `.cmd` + resolving npm + cache/rejestr) potrafił budżet przekraczać → `Request 'initialize' timed out` (powtarzalne w `vibe.log` od 2026-11-22, w trzech wersjach przypiętych), a na cache-miss prompt instalacji npx zjadałby request `initialize` prosto ze stdin serwera. Globalny binarny startuje w ułamku sekundy, więc cała klasa awarii znika; brak instalacji daje od razu czytelny błąd spawn zamiast hang-u. Ponieważ manifest niesie już tylko nazwę komendy, wersja żyje w globalnym installu użytkownika (współdzielonym z innymi narzędziami) — dlatego linia instalacyjna README to `npm i -g @playwright/mcp@latest`, a polityka „przypięte, nigdy `@latest`" (`mcp-pins` w `bundles.yaml`) została świadomie zlikwidowana: pin wymuszałby downgrade komuś, kto ma nowszy binarny, i niczego już nie chronił. `checkPlaywrightInstallDoc` (wywoływany w każdym trybie jak `checkMembership`) pilnuje teraz tylko, żeby linia `npm i -g @playwright/mcp@latest` nie zniknęła z README (przypięta wersja w linii też failuje — ślad starej polityki). Testy: asercje builda na bare command + test bramki (brak README, przypięta wersja odrzucona, obecność `@latest`); 54/54 testów zielonych.
